# cBound

Ada bindings to a collection of C and C++ libraries.

The bindings are generated by a companion project, [swig4ada](https://github.com/charlie5/swig4ada).


## The bindings

| Binding        | Library                              | Thick layer        | Demos                                   |
|----------------|--------------------------------------|--------------------|-----------------------------------------|
| `swig`         | Support packages for every binding   |                    |                                         |
| `clib`         | The standard C library               |                    | `simple`                                |
| `fann`         | FANN neural networks                 |                    | `simple`                                |
| `gmp`          | GNU multiple precision arithmetic    | `GMP.discrete`     | `minimal`                               |
| `opencv`       | OpenCV 5 computer vision             | `openCV.*`         | `simple`, `images`, `contours`, `video` |
| `speech_tools` | Edinburgh speech tools               |                    |                                         |
| `tensorflow`   | The TensorFlow C interface           |                    | `hello_tf`                              |
| `xcb`          | The X protocol C binding             |                    | `simple`                                |
| `festival`     | Festival speech synthesis            |                    | `say_hello`                             |

The bindings are arranged in tiers: a binding may use those of a lower tier (`festival`, in tier 2, uses `speech_tools`).

Each needs its library, and the headers of its library, installed on the system.


## Install

Add the following lines to `~/.bashrc`, or its equivalent:

    export CBOUND=/path/to/cbound
    source $CBOUND/cbound-gpr_paths.sh

A project then uses a binding by naming it in its project file:

    with "gmp";


## The layout of a binding

    generate/        The swig interface file, and the 'builder' which generates the binding from it.
    source/thin/     The generated binding: Ada specifications and a C or C++ wrapper file.
    source/          A thick binding, where there is one.
    library/         The project files.
    applet/          Demos and tests.

The thin binding follows the library closely, name for name. A thick binding, where there is one, is what an Ada
program would rather use: it has Ada types and strings, raises exceptions, and frees what it allocates.


## Checking the bindings

    ./check_all

builds each binding, and builds and runs its demos, and says which fail. A demo which needs a display or makes a
sound is only built. It is worth running after a change to swig4ada, or to a library of the system. A binding may
be named, to check it alone:

    ./check_all opencv


## Generating a binding again

With swig4ada installed, from within a binding:

    cd generate
    ./builder
    ./export_source

The first generates the binding in place, and compiles its wrapper file. The second moves it into `source/thin`.

A wrapper file checks, when it is compiled, that each structure of the library has the size, and each of its members
the place, which the Ada record takes it to have. A binding which is generated on one machine and built on another,
where they differ, then fails to build, and must be generated again there.
